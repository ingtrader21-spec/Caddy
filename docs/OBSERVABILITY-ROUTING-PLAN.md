# Observability Browser Routing Plan

## Canonical A target
All approved observability/security DNS names resolve to `37.27.128.39` with TTL `600`.

## Browser-facing routes
Caddy may publish only these browser-facing hosts from this stack:

- `graf.codestra.media` -> Grafana web UI
- `supe.codestra.media` -> Superset web UI
- `bao.codestra.media` -> OpenBao UI/API only when protected by strong authentication, strict authorization/network policy, TLS, security headers, rate limits, and audit controls

Caddy terminates TLS and forwards only to the approved private upstream for each service. Upstream container/native ports must not be separately exposed to the public Internet.

## Not browser/public routes
Do not create public Caddy routes for native service endpoints of:

- `prom.codestra.media`
- `aler.codestra.media`
- `loki.codestra.media`
- `temp.codestra.media`
- `otel.codestra.media`
- `node.codestra.media`
- `cadv.codestra.media`
- `pgex.codestra.media`
- `rdex.codestra.media`
- `blac.codestra.media`
- `allo.codestra.media`

These names may exist in DNS but service access remains private/allowlisted.

## Security requirements
- TLS certificate must match the exact canonical hostname.
- Do not expose Caddy admin API publicly.
- Strip/avoid forwarding untrusted identity headers unless explicitly generated by the trusted authentication boundary.
- Set appropriate security headers for browser UIs.
- Never log Authorization headers, cookies, OpenBao tokens, recovery material, or secret-bearing query parameters.
- Health checks must not bypass authentication to expose sensitive application state.
- No route may make Grafana, Superset, or OpenBao an alternate write path into provider systems.

## Change gate
Before reload: validate Caddy configuration, resolve DNS, verify upstream privately, confirm firewall policy, obtain certificate in staging/controlled rollout, then smoke-test HTTPS/auth. Keep rollback to the previous known-good Caddy config.
